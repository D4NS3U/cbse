- Alpha4 wire payloads retain the legacy `project` field for fixture compatibility and add non-JSON `ProjectNamespace`/`ProjectName` fields populated after subject parsing, keeping the transport-neutral types decoupled from NATS while remaining byte-compatible with existing fixtures.

- The lifecycle package depends on a transport-neutral `MessagingCleaner` interface (`DeleteTranslatorConsumer`, `PurgeSubject`) and a `ProjectStore` interface over high-level persistence operations, because `*sql.DB.QueryRowContext` returns the concrete `*sql.Row` which cannot be faked. A `JetStreamDeletion` interface in lifecycle declares explicit `natsgo` signatures so a real NATS client structurally satisfies the messaging package's unexported `consumerManager`/`streamPurger` interfaces without exporting them; a `NATSDeletionClient` adapter wires that at runtime.
- `PurgeSubject` performs a subject-filtered purge (`StreamPurgeRequest{Subject}`) and treats `ErrStreamNotFound` as success so a missing stream satisfies cleanup. The ordered deletion cleanup deletes and confirms runner Jobs, then deletes the SM-owned Translator consumer, then purges three subjects (EDS batch, Translator request, Translator-ready wildcard) on the two shared streams, then deletes the project row, then re-confirms runner Jobs are absent, and only then removes the SM finalizer. Any failure before the finalizer removal leaves the finalizer in place so the reconciler retries; the fake client completes deletion once the finalizer is removed on a deleting object.
- DB and NATS integration tests carry the `integration` build tag and skip locally when their env-gating inputs (DSN/user/password for Postgres, `SCENARIO_MANAGER_NATS_URL` for NATS) are absent, matching the existing `bssl_integration_test.go`/`coredbconnect_test.go`/`natsconnect_test.go` pattern; they compile under `make test-fast`'s `go test -tags=integration -run '^$' ./...` gate and are available for CI.
